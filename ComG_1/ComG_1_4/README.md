# 1-4 사각형 애니메이션

Visual Studio에서 `ComG_1.slnx`를 열고 `ComG_1_4`를 시작 프로젝트로 선택한 다음 Debug / x64로 실행한다.

## 파일 구성

모든 설정, 구조체, 전역 변수, 함수 선언, main 및 함수 구현은 기존 파일인 `ComG_1_4.cpp` 하나에 들어 있다. 별도의 사용자 헤더나 CPP 파일은 사용하지 않는다.

## 설정

`ComG_1_4.cpp` 상단의 `#define`을 수정한 뒤 다시 빌드한다.

| 설정 | 기본값 | 의미 |
|---|---:|---|
| WINDOW_WIDTH / WINDOW_HEIGHT | 1200 / 1200 | 처음 열리는 창 내부 영역의 크기 |
| WINDOW_MIN_WIDTH / WINDOW_MIN_HEIGHT | 300 / 300 | 최소 창 내부 크기 |
| MOVE_STEP | 2.0f | 타이머 한 단계의 이동 거리 |
| TIMER_INTERVAL_MS | 1 | 논리적 갱신 간격(ms), 양수여야 함 |
| SIZE_STEP | 2.0f | 한 단계마다 변하는 너비 또는 높이 |
| RECT_MIN_SIZE / RECT_MAX_SIZE | 50 / 150 | 처음 크기 및 크기 변화 범위 |
| ZIGZAG_VERTICAL_DISTANCE | 100 | 지그재그에서 한 번의 수직 구간 길이 |
| MAX_RECTS | 5 | 생성 가능한 최대 개수 |

배경은 `glClearColor(0.2f, 0.2f, 0.2f, 1.0f)`로 고정한다. 색상의 각 RGB 성분은 0.10~0.90 사이에서 독립적으로 추출한다.

## 입력과 상태

왼쪽 클릭으로 사각형을 생성한다. 중심을 창 안쪽으로 보정한 뒤 그 위치를 `originalX`, `originalY`에 저장한다. 여섯 번째 클릭부터는 무시한다.

`Motion` 열거형 하나에 현재 위치 동작을 저장하므로 1, 2, 3은 동시에 활성화되지 않는다. 같은 키를 다시 누르면 멈추고, 다시 누르면 재개한다. 4는 별도 `resizing` 플래그를 토글한다. 3을 켜면 크기 변화는 꺼지고, 3이 실행 중일 때 4는 무시한다. 5는 누른 순간에만 모든 색상을 다시 추출한다.

`s`는 위치와 크기 변화 모두 정지, `m`은 기존 위치 동작을 원위치 복귀로 교체하되 크기 변화 유지, `r`은 사각형과 애니메이션 상태 초기화, `q`는 종료이다. 색상은 지속 애니메이션이 아니므로 m을 눌러도 현재 색상이 유지된다.

기존 코드처럼 InputProcess에서 키를 확인한다. KeyPressed는 이전 프레임의 키 상태를 기억해 누르기 시작한 순간에만 true를 반환하므로 길게 눌러도 한 번만 토글된다.

## 실시간 창 크기 변경과 충돌

`GLFW_RESIZABLE`을 켜고 `glfwSetWindowSizeCallback`에 `WindowSizeCallback`을 등록한다. 창 크기가 바뀌면 다음 순서로 처리한다.

1. `ResizeWindow(width, height)`로 현재 창 크기를 저장한다.
2. 모든 사각형 중심을 새로운 유효 범위로 보정한다. 크기 자체는 변경하지 않는다.
3. 가장자리 이동 상태라면 기존 경로를 무효화하고 새 창의 위쪽으로 재집결한다.
4. `DrawScene`을 호출해서 창 테두리를 드래그하는 중에도 출력 영역을 다시 맞춘다.

너비 w, 높이 h인 사각형 중심의 유효 범위는 다음과 같다.

```cpp
w / 2 <= x && x <= windowWidth  - w / 2
h / 2 <= y && y <= windowHeight - h / 2
```

중심만 0~창 너비로 제한하면 사각형 절반이 밖으로 나갈 수 있으므로 반쪽 크기를 제외한다. 이 범위는 생성, 창 축소, 크기 변화, 벽 반사, 복귀 목표 보정에 모두 사용된다.

좌표는 왼쪽 위가 (0, 0), 오른쪽이 +x, 아래가 +y이다. GLFW의 마우스 좌표와 같은 방향이라 클릭 좌표를 그대로 사용할 수 있다. 창 크기가 바뀌어도 기존 좌표와 사각형 크기에 비율을 곱하지 않는다.

출력 시 `glOrtho(0, windowWidth, windowHeight, 0, -1, 1)`로 현재 창 크기에 맞는 투영을 설정한다. `glViewport`에는 `glfwGetFramebufferSize`로 얻은 실제 렌더링 픽셀 수를 전달한다. Windows 배율 설정에서 논리적인 창 크기와 물리적인 픽셀 수가 다를 수 있기 때문이다. 여기서 MOVE_STEP의 픽셀은 GLFW 창 좌표 단위이며, 배율 100%에서는 화면 픽셀과 일치한다.

사각형의 크기를 유지하면서 창 안에 완전히 넣으려면 창이 최대 사각형보다 작아질 수 없어야 한다. 따라서 `glfwSetWindowSizeLimits`로 최소 내부 크기를 300×300으로 지정했다. 최소화 시에는 갱신을 중단하고 0 크기 프레임버퍼에 그리지 않는다.

## 이동 계산

### 1: 대각선

각 사각형은 독립적인 `dx`, `dy` 방향(±1)을 가진다. 전체 이동 거리가 2가 되도록 각 축에는 `MOVE_STEP / sqrt(2)`를 적용한다. 벽에 닿으면 해당 축 방향만 반전한다. 모서리에서는 두 축이 모두 반전된다. `Bounce`는 경계까지 간 후 남은 이동량을 반대 방향으로 사용한다.

### 2: 가로 지그재그

`zigzagVertical == false`이면 좌우 벽을 향해 수평 이동한다. 벽에 도착하면 수평 방향을 뒤집고 `verticalRemaining = 100`으로 수직 단계를 시작한다. 수직 단계에서는 한 번에 최대 2만큼 이동하고 잔여 거리를 줄인다. 100을 다 이동하면 수평 이동으로 돌아간다. 위·아래 벽에 닿으면 `dy`를 반전하며, 수직 구간의 남은 거리도 이어서 이동한다. 따라서 세로 공간이 100보다 작아도 밖으로 나가지 않는다.

### 3: 집결 후 시계방향

가장자리 이동을 시작할 때 모든 사각형을 50×50으로 초기화하고 크기 변화 단계도 0으로 되돌린다. 먼저 각 사각형을 위쪽 목표까지 2씩 이동시킨다. 도착 여부를 `attachedToTop`에 저장하며 먼저 도착한 사각형은 기다린다. 모두 도착한 다음 갱신부터 시계방향 이동을 시작한다.

경로의 가로 길이를 Lx, 세로 길이를 Ly라 하면 둘레는 `P = 2 * (Lx + Ly)`이다. 각 사각형은 경로상의 거리 `edgeDistance`를 갖는다.

```cpp
edgeDistance = fmod(edgeDistance + MOVE_STEP, perimeter);
```

거리가 속한 구간에 따라 위쪽(오른쪽), 오른쪽(아래), 아래쪽(왼쪽), 왼쪽(위) 좌표로 변환한다. 각 사각형마다 벽 충돌 후 방향을 바꾸는 대신 같은 경로에 동일한 거리를 더하므로 모서리에서 이동량이 손실되지 않는다. 두 사각형 사이의 경로상 거리 차이도 일정하다. 여기서 유지되는 간격은 경로를 따라 잰 간격이며, 모서리 전후의 직선거리는 달라질 수 있다. 같은 x 위치에 집결한 사각형은 겹친 채 움직인다.

모든 사각형이 50×50이므로 중심을 벽에서 25만큼 떨어뜨린 공통 경로를 사용하면 각 사각형이 벽에 정확히 붙는다. 정지 후 재개할 때도 50×50 상태가 유지되며 기존 경로를 이어간다. 가장자리 이동 중 사각형을 추가하거나 창 크기를 바꾸면 전체를 다시 집결시켜 경로를 설정한다.

### 4: 크기 변화

`sizePhase`는 0~3을 순환한다.

```text
0: 너비 50 유지, 높이 50 → 150
1: 너비 50 유지, 높이 150 → 50
2: 높이 50 유지, 너비 50 → 150
3: 높이 50 유지, 너비 150 → 50
```

중심을 기준으로 위아래 또는 좌우로 늘고 줄며, 커져서 벽을 넘을 때만 중심을 안쪽으로 보정한다. 중간에 끄면 현재 크기와 단계가 유지된다.

### m: 원위치 복귀

목표와 현재 위치의 차이 벡터 `(dx, dy)`를 계산한다. 길이를 d라고 하면 `(dx/d, dy/d) * MOVE_STEP`만큼 이동한다. 목표까지 거리가 2 이하일 때 정확한 목표 좌표로 맞춰 지나치거나 떨리지 않게 한다. 창이 줄었거나 현재 크기가 커서 원래 좌표가 유효하지 않으면 현재 창에서 가능한 가장 가까운 위치를 목표로 사용한다. 저장된 최초 좌표 자체는 바꾸지 않는다.

## 타이머 함수의 의미

이 프로젝트는 GLFW를 사용한다. `TimerFunction`은 GLFW 내장 타이머 콜백이 아니라 이 프로그램에서 작성한 고정 간격 갱신 함수이다.

- `glfwGetTime()`은 GLFW 초기화 후 경과 시간을 초 단위 double로 읽는다. 시간을 읽을 뿐 함수를 예약하거나 실행하지 않는다.
- `nextTick`에는 다음 논리적 갱신 예정 시각을 저장한다.
- 현재 시각이 `nextTick`에 도달하면 `UpdateAnimation()`을 호출하고 예정 시각에 `TIMER_INTERVAL_MS / 1000.0`초를 더한다.
- 렌더링 때문에 여러 간격이 지났다면 `while`로 여러 번 갱신한다. 한 번의 갱신은 항상 MOVE_STEP만큼 이동하므로 프레임마다 2픽셀 이동하는 방식과 다르다.
- 다음 예정 시각까지 시간이 남으면 `glfwWaitEventsTimeout(wait)`로 이벤트 또는 시간 만료를 기다린다. 이벤트가 들어오면 일찍 깨어날 수 있으므로 실제 갱신 여부는 다시 `glfwGetTime()`으로 판단한다.

1ms는 이 프로그램이 선택한 최소 정수 밀리초 설정값이며, GLFW나 Windows가 보장하는 정확한 호출 주기가 아니다. OS 스케줄링, 수직 동기화, 프레임 출력 시간에 따라 실제 처리 시각은 늦어질 수 있다. 기본 설정의 논리적 이동 속도는 `2 / 0.001 = 2000` 좌표 단위/초이다. 너무 빠르면 TIMER_INTERVAL_MS를 10으로 바꾸면 200/초가 된다. 0ms는 허용하지 않는다.

Windows에서 창 크기 조절이나 이동 중 OS의 모달 이벤트 루프가 메인 루프를 잠시 막을 수 있다. 창 크기 변경 콜백은 즉시 경계와 출력을 갱신하지만 그동안 애니메이션이 매 1ms 실행된다고 보장하지 않는다. 0.1초 넘게 지연되었을 때는 밀린 갱신을 버려 조작 종료 직후 사각형이 갑자기 멀리 이동하는 일을 방지한다.

공식 문서: [GLFW 시간 및 이벤트 처리](https://www.glfw.org/docs/latest/input_guide.html), [창 크기 및 프레임버퍼 콜백](https://www.glfw.org/docs/latest/group__window.html).

## 검증

기존 애니메이션 로직을 전역 변수와 독립 함수 형태로 옮겼다. 이전 분리형 구현의 테스트 파일과 헤더는 제거했다. 통합 파일은 Debug x64 빌드로 확인하며 GUI 시각 검증은 별도로 수행하지 않았다.
